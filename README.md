# Excel — Portfolio

A static, two-page portfolio site. No build step, no framework, no dependencies — plain HTML, CSS
and JavaScript. Open `index.html` in a browser and it works, including the open-source cards,
which read generated data from `data/repos.js`.

```
index.html                        home page: work, research, stack, about, contact
contact.html                      contact page: details, socials, message form
css/styles.css                    all styling for both pages
js/main.js                        theme toggle, clipboard, clock, scroll spy
js/contact.js                     form validation and delivery
js/repos.js                       renders the open-source repository cards
data/repos.js                     generated repository data, loaded as a script
data/repos.json                   the same data as plain JSON
assets/                           favicon, app icons, Open Graph image, web manifest
tools/make-assets.py              regenerates the icons and the OG card
tools/fetch-repos.py              fetches repositories from the GitHub API
.github/workflows/update-repos.yml  daily repository refresh
```

### 3. The contact form — pick how messages arrive

Open `js/contact.js` and look at `CONFIG`:

```js

  endpoint: "",

```

**`endpoint: ""` (the default)** — the form hands the message to the visitor's own mail app via a
`mailto:` link, with the name, email, subject and body already filled in. No setup, no account,
no third party. The visitor has to press send in their mail app. Without JavaScript the form still
works, because the `<form>` carries a matching `action="mailto:..."` fallback.

**`endpoint: "https://formspree.io/f/xxxxxxxx"`** — messages arrive on their own. Sign up for a
free Formspree account, create a form that points at `israelexcel2006@gmail.com`, and paste the
endpoint in. Any service that accepts a JSON POST with the same field names (`name`, `email`,
`subject`, `message`) works the same way.

The form validates in the browser (required fields, email format, minimum message length), shows
errors inline, moves focus to the first bad field, and includes a hidden honeypot field that
silently discards bot submissions.

### 5. GitHub repositories (automatic)

The "Open source" block under Selected work reads `data/repos.js`. The same payload is also written
to `data/repos.json`. Both are regenerated by `.github/workflows/update-repos.yml` every day at
04:17 UTC, and can also be run by hand from the repository's
**Actions → Refresh GitHub repositories → Run workflow** button. The `.js` file is loaded with a
`<script>` tag, so it works even when `index.html` is opened directly from disk; the JSON file is
there for anything that wants the raw data.

How it selects repositories, in `tools/fetch-repos.py`:

1. Pinned repositories, when the workflow's token can read them.
2. Names in the `FEATURED` list, in the order listed.
3. The most recently updated repositories, as a fallback.

Repositories in `EXCLUDE` are never published. Change `FEATURED`, `EXCLUDE` or `REPO_LIMIT` in the
script to control the block. `GITHUB_USER` defaults to `xlisrael`; override it in the workflow if
the username ever changes.

The workflow uses the built-in `GITHUB_TOKEN` and only commits when `data/repos.json` actually
changed. On GitHub Pages or a connected Vercel/Netlify project, that commit triggers the normal
deployment, so nothing else needs to be wired up. If the commit step is rejected, check
**Settings → Actions → General → Workflow permissions** and allow read and write access.

To refresh the data locally:

```bash
GITHUB_USER=xlisrael python3 tools/fetch-repos.py
```

A token is optional locally. Without one, GitHub's unauthenticated rate limit applies and pinned
repositories are skipped. With one, pinned repositories are included:

```bash
GITHUB_TOKEN=ghp_xxxxxxxx GITHUB_USER=xlisrael python3 tools/fetch-repos.py
```

`js/repos.js` renders the cards client-side. It uses the embedded `data/repos.js` payload first,
then falls back to fetching `data/repos.json`. If both fail, the page keeps its "All repositories"
link and shows a short fallback message. Without JavaScript, the block keeps its fallback link to
the GitHub profile.

## Deploying

The site is fully static, so any of these work:

- **GitHub Pages** — push the folder, then *Settings → Pages → Deploy from a branch*.
  Your site will be at `https://<user>.github.io/<repo>/`.
- **Netlify / Vercel / Cloudflare Pages** — drag the folder in, or connect the repo. Build
  command: none. Publish directory: `.` (the repository root).
- **Any web server** — copy the files to the document root.

Two things to know:

- The contact links and the clipboard button need `https://` (or `localhost`) for the Clipboard
  API. Over plain `http://` the page falls back to a hidden-textarea copy, which still works.
- Fonts come from Google Fonts, so visitors need a network connection. The page falls back to
  system fonts gracefully if they do not.

### Testing locally

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

## What's in it

**Layout** — a single left-aligned editorial column. Project rows split into a text column and a
mono "evidence" column, which is where the module breakdown and the allow-list rules live.

**Two pages** — `index.html` carries the content (work, research, stack, about, contact details).
`contact.html` pulls out the contact material: quick-action buttons (email, call, WhatsApp), the
full details list, the follow-me links, and the message form. The header nav links across both
pages, and the contact link is marked `aria-current="page"` on `contact.html`.

**Open source** — a repository grid under Selected work reads the generated `data/repos.json`.
`js/repos.js` builds the cards with DOM APIs, so GitHub-supplied text is never injected as HTML.
Each card shows the language, last push, stars when present, topics and links to the code and any
live URL. A daily GitHub Action keeps the data fresh.

**Theme** — light and dark, following the OS by default. The toggle in the header overrides it
and the choice is remembered in `localStorage`. A tiny inline script in `<head>` applies the
saved theme before first paint, so there is no flash of the wrong colours.

**Accessibility** — single `<h1>`, one landmark per region, a skip link, `aria-current` on the
active nav item, visible focus rings, `aria-invalid` plus inline error text on the form, and
`prefers-reduced-motion` honoured throughout. The colour pairs all clear WCAG AA (4.5:1) in both
themes.

**SEO / sharing** — description, canonical URL, Open Graph and Twitter card tags, a `Person`
JSON-LD block, a web app manifest, and a matching favicon set.

**Performance** — no JavaScript frameworks, no render-blocking font CSS (it is preloaded and
applied asynchronously), inline SVG icons, and no third-party requests beyond the font files.

**Responsive** — verified with no horizontal overflow at 320, 375, 414, 768, 1024 and 1440px.
The header nav tightens its type below 430px so all five links plus the theme toggle stay on one
row on the narrowest phones.

## Editing the content

| To change…                | Edit                                            |
| ------------------------- | ----------------------------------------------- |
| The name and tagline      | `index.html` — `.hero` block                    |
| A project                 | `index.html` — the `<article class="project">` in `#work` |
| The module list           | the `.evidence` `<figure>` inside that project  |
| Which repos appear        | `tools/fetch-repos.py` — `FEATURED` / `EXCLUDE` |
| The stack cards           | `index.html` — the `.stack` block in `#stack`   |
| The About bullets         | `index.html` — the `.ticks` list in `#about`    |
| Contact details           | `index.html` — the `.contact-list` in `#contact` |
| Quick actions / socials   | `contact.html` — `.quick-actions` and `.socials` |
| The form fields           | `contact.html` — the `.msg-form` block          |
| Form behaviour            | `js/contact.js` — `CONFIG` and the validation rules |
| Colours, spacing, type    | `css/styles.css` — the `:root` token block      |
| Section order / spacing   | `css/styles.css` — `.wrap` and `main` gaps      |

Colours live in one place. Change `--accent` and the kicker, links, status dots, focus rings
and the copy button all follow:

```css
:root {
  --bg: #eef1ef;
  --surface: #e2e8e4;
  --fg: #13201b;
  --muted: #55645d;
  --muted-dim: #5d6c64;
  --line: #c3cec8;
  --accent: #0c6a52;
  --alert: #b03d1c;
}
```

Dark values are repeated in two places — the `@media (prefers-color-scheme: dark)` block and the
`:root[data-theme="dark"]` block. Keep them in sync, or remove the media query block entirely
and rely on the toggle.

If you change `--accent` or `--alert`, re-check contrast: the text pairs need 4.5:1 against
both `--bg` and `--surface`.
